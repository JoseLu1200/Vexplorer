# Reparación de UX y recorrido de Vexplorer

**Objetivo:** corregir los problemas de uso denunciados por el usuario mediante reproducción en navegador, cambios acotados y revisión visual iterativa.

**Dirección autorizada:** consola técnica más sobria, menos redondeada y menos apelotonada; mantener el plano protagonista y todas las funciones de inspección, revisión, biblioteca, coste y traza. Mostrar un resumen legible y permitir abrir evidencia detallada sin perder procedencia.

**Arquitectura:** conservar HTML/CSS y módulos ES existentes, API real y datos revisables. Un escritor por archivo principal; pruebas en instancia aislada y revisión del conjunto antes del despliegue.

## Restricciones

- No sustituir desconocidos por números ni hipótesis por hechos.
- No ocultar procedencia, unidades o errores necesarios para decidir.
- Conservar rutas, IDs, exportaciones y revisiones existentes.
- No añadir frameworks ni llamadas pagadas para verificar cambios visuales.
- Preservar cambios locales previos; no publicar datos QA como históricos reales.

## Trabajo y evidencia de aceptación

- [x] Layout: corregir alturas y overflow en escritorio, móvil, poca altura y zoom; las últimas filas y acciones son alcanzables y no se solapan.
- [x] Interacción: paneles alcanzables al navegar, mensajes claros, acciones/capacidades coherentes, revisión y errores reproducidos.
- [x] Densidad: radios contenidos, texto auxiliar plegable y jerarquía clara sin eliminar evidencia.
- [x] Visor: canvas responde a raíl, ventana y visibilidad; tema y selección conservados; recursos liberados.
- [x] QA real: mesa completa, piezas separadas, caso incompleto, revisión, descargas, biblioteca/coste, traza, tema y persistencia.
- [x] Skills: verificar fuentes originales e instalar pocas guías complementarias con commit/ruta registrados.
- [x] Integración: suite frontend fresca, revisión del diff y capturas a 390, 1100 y 1440 px; pruebas adicionales a baja altura.
- [x] Despliegue: preparar artefactos verificables, preservar datos/configuración y comprobar el servicio publicado cuando el acceso esté disponible.

## Fallos que deben comprobarse explícitamente

1. Contenido largo y campos con identificadores extensos no empujan ni recortan las acciones.
2. Tabla o panel más altos que la pantalla permiten llegar al final con rueda/teclado.
3. Cambiar el panel en móvil lleva a contenido visible, manteniendo navegación recuperable.
4. Contraer el menú no deforma el canvas 3D ni pierde selección.
5. Resultado parcial y ausencia de artefactos no presentan controles engañosos ni errores silenciosos.
